Education & Integrity Framework

IBM Bob for Students & Academic Projects

A complete architecture for deploying IBM Bob to students across all courses and general development, enforcing academic attribution, logging prompt histories, and verifying code provenance without requiring Git.

1. System Overview & The Core Challenge

When providing IBM Bob Free Trial accounts to college students, administrative dashboards (such as Enterprise Bobalytics) are unavailable. Standard code generated by any AI is standard plain-text without embedded cryptographic signatures.

This framework establishes a workspace architecture that runs directly inside the student's local IDE to guarantee:

🏷️ Mandatory Watermarking

Every file generated or edited with Bob automatically receives a standardized academic header comment.

💬 Prompt History Capture

All student prompts, questions, and reasoning are continuously recorded into PROMPT_HISTORY.md.

📑 Audit Trail Logging

Architectural decisions, algorithms chosen, and unit test results are recorded in AI_AUDIT_TRAIL.md.

📦 Flexible Submissions

Works seamlessly with ZIP archives, LMS folder uploads, direct file transfers, or Git.

2. Student Step-by-Step Workflow

The student experience is designed to be seamless, interactive, and transparent across any course or project:

1

Open Project & Fill Profile

Student opens the folder in VS Code with IBM Bob, and fills in their Name and ID in STUDENT_INFO.json.

2

Select Mode: 🎓 Student Developer

In the Bob chat panel mode dropdown, student selects student-dev mode. This activates Socratic mentoring and provenance tracking.

3

Interactive Coding & Automated Tracking

Student prompts Bob for assistance. Bob explains concepts, writes clean code with attribution headers, and logs prompts to PROMPT_HISTORY.md.

4

Package & Verify Submission

Student runs /package-submission in Bob chat. Bob verifies all files, checks audit logs, and generates SUBMISSION_REPORT.md.

5

Submit via LMS / ZIP / Folder

Student uploads their project folder or ZIP archive directly to the course LMS or instructor portal.

3. Custom Mode: 'Student Developer' (student-dev)

Configured in .bob/custom_modes.yaml, this mode guides students as an academic programming mentor:

  • Socratic Guidance: Explains logic, data structures, and trade-offs before generating code.
  • Enforced Watermarking: Ensures generated code includes student metadata and Bob provenance.
  • Automatic Logging: Keeps PROMPT_HISTORY.md and AI_AUDIT_TRAIL.md continuously updated.
  • Permission Groups: Granted read, edit, execute, skill, and todo tools.
# .bob/custom_modes.yaml
customModes:
  - slug: student-dev
    name: 🎓 Student Developer
    description: General AI programming mentor for students using IBM Bob across all courses.
    groups:
      - read
      - edit
      - execute
      - skill
      - todo

4. Integrated Skills Reference

Skills provide structured, repeatable workflows accessible via slash commands:

Skill Command Location Purpose & What It Does
/package-submission .bob/skills/package-submission/ Runs verify_submission.py, audits watermark compliance, verifies prompt history, and produces SUBMISSION_REPORT.md.
/export-chat-history .bob/skills/export-chat-history/ Formats and synchronizes active conversational prompts and Bob responses into PROMPT_HISTORY.md.
/log-activity .bob/skills/log-activity/ Appends a structured milestone entry (objective, files, design rationale, test proof) to AI_AUDIT_TRAIL.md.

5. Workspace Rules & Watermarking Standards

Defined in .bob/rules/academic-attribution.md, these rules load automatically on every Bob prompt without requiring manual student activation.

Language-Specific Header Formats:

/*
 * [IBM Bob Academic Attribution]
 * Student Name: Jane Doe | Student ID: STU123456
 * Course / Project: Computer Science / Coursework
 * Generated/Assisted with: IBM Bob
 * Timestamp: 2026-10-15 14:22:10
 */

6. Deployment Guide for Instructors

How to distribute this template to students:

Option 1: Direct ZIP Archive / LMS Download (Recommended)

1. Compress this folder into a `.zip` archive.
2. Upload it to your course portal or LMS (Canvas, Blackboard, Moodle).
3. Students extract and open the folder in VS Code. All Bob rules and modes load immediately upon startup.

Option 2: Git Template / Classroom (Optional)

If your course uses Git, host as a template repository on GitHub/GitLab. Students can clone it directly.

7. Instructor Verification & Evaluation

When grading student submissions, follow this simple verification check:

  1. Run Automated Verifier: 
    python3 .bob/skills/package-submission/verify_submission.py
    Inspect the JSON output for watermarked_files, prompt_history.prompt_count, and audit_trail.entry_count.
  2. Audit Prompt Progression (PROMPT_HISTORY.md): Verify that student prompts show natural, stepwise inquiry and genuine problem-solving.
  3. Audit Milestone Trail (AI_AUDIT_TRAIL.md): Verify that key algorithms and tests were logged with clear technical rationale.
